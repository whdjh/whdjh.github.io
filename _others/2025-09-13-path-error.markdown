## 왜 공부하게 되었나

1 → 2 → 3번 버튼 네비게이션을 만들다가, 마지막 이동이 의도와 다르게 동작하는 버그를 겪었다.  
원인은 세 번째 링크의 href가 슬래시(/) 없이 적힌 상대 경로라서, 라우터가 현재 경로를 기준으로 경로를 합성한다는 점이었다.

---

## 문제 상황

```tsx
// 의도: /path1 → /path2 → /path3 로 이동
<Link href="/path1" />
<Link href="/path2" />
<Link href="path3" /> // 상대 경로라 현재 경로에 붙는다.
```

- 실제 이동: /path1 → /path2 → /path2/path3
- 원인: `"path3"`가 루트 기준이 아닌 상대 경로라서, 현재 URL(/path2) 아래로 붙는 방식으로 해석됨

---

## 공부 내용

- 내부 링크는 기본적으로 항상 `/`로 시작하는 절대 경로를 쓰는 것이 안전하다.
- 브라우저와 라우터는 href가 `/`로 시작하지 않으면 현재 문서 URL을 base로 삼아 상대 경로를 합성한다.

다음 규칙을 기억하면 된다.

| 작성 | 의미 | 이동 결과 |
|------|------|-----------|
| `"/path3"` | 루트 기준 절대 경로 | `/path3` |
| `"path3"` | 상대 경로 | `/현재경로/path3` |
| `"./path3"` | 현재 경로 기준 | `/현재경로/path3` |
| `"../path3"` | 한 단계 상위 | 상위 경로 + `/path3` |

- Next.js에서는 App Router든 Pages Router든 `<Link href>` 문자열이 `/`로 시작하면 절대, 아니면 상대로 해석된다.
- 동적·중첩 라우트에서만 예외적으로 `../` 같은 상대 경로를 쓰고, 그 외에는 일관되게 절대 경로를 사용하는 것이 좋다.

---

## 결과

세 번째 링크를 href="/path3" 로 수정해 /path1 → /path2 → /path3 로 의도한 대로 이동하도록 수정했다.
