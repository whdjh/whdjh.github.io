## 왜 공부하게 되었나?

부트캠프에서 빠른 속도로 React를 사용했지만, 근본적으로 왜 React를 쓰는지 이해하지 못했다.
React의 장점과 설계 철학을 이해하면 상태 관리와 UI 구성 방법을 더 잘 활용할 수 있다고 판단하여 공부하게 되었다.

---

## 문제 상황

기존 방식으로는 상태(state) 변경 시 UI를 직접 업데이트해야 하므로 코드가 복잡해지고 오류가 발생하기 쉬웠다.
컴포넌트 재사용과 전역 상태 관리가 어려워 프로젝트 규모가 커지면 유지보수가 힘들었다.

---

## 공부 내용

### Virtual DOM

실제 DOM을 직접 조작하지 않고 메모리 상의 가상 DOM에서 UI 변경을 계산하여 효율적으로 렌더링한다.

```tsx
const [count, setCount] = useState(0);

return (
  <div>
    <p>{count}</p>
    <button onClick={() => setCount(count + 1)}>증가</button>
  </div>
);
```

상태가 바뀌면 Virtual DOM에서 변경점을 계산 후 실제 DOM만 업데이트한다.

#### 근데 과거에 React가 없었을 때는 어떻게 했을까?

과거에는 상태가 바뀔 때마다 개발자가 직접 DOM을 찾아서 업데이트해야 했다.
사용자 입력이나 이벤트에 따라 여러 요소를 일일이 갱신하고, 화면 일관성을 유지하려면 복잡한 조건문과 반복 로직을 작성해야 했다.
이 과정에서 UI가 꼬이거나 버그가 생기는 일이 많았고, 재사용 가능한 컴포넌트 구조를 만들기도 어려웠다.
React는 이런 문제를 해결하고, 상태 기반 선언형 UI와 Virtual DOM으로 개발을 훨씬 직관적이고 안정적으로 만들어 준다.

### 컴포넌트화

UI를 재사용 가능한 컴포넌트 단위로 나눌 수 있으며, props와 state로 데이터와 동작을 전달한다.

```tsx
function Button({ onClick, children }) {
  return <button onClick={onClick}>{children}</button>;
}

<Button onClick={() => setCount(count + 1)}>증가</Button>
```

### 상태 관리 용이성

React는 선언형 UI 라이브러리이므로, 상태(state)가 바뀌면 UI가 자동으로 업데이트된다.
상태 관리를 통해 여러 컴포넌트 간 UI 일관성을 유지하기 용이하다.

---

## 결과: 이제는 이렇게 정리할 수 있다

- 상태와 UI가 바인딩되어 있어, 상태 변경 시 UI를 직접 제어할 필요가 없어졌다.
- 컴포넌트 단위로 재사용 가능한 구조를 만들 수 있어 유지보수가 쉬워졌다.
- 전역 상태 관리 도입으로 프로젝트 규모가 커져도 UI 일관성을 유지할 수 있게 되었다.

---

## 마치며

React를 쓰는 이유는 결국 **선언형 UI와 상태 기반 렌더링**이다.

- “이 상태면 이 UI”라고 선언해 두면 → React가 Virtual DOM으로 필요한 부분만 갱신한다.
- 컴포넌트로 쪼개 두면 → 재사용과 유지보수가 쉬워진다.

왜 React를 쓰는지 이해하고 나니, 상태 설계와 컴포넌트 구조를 더 의도적으로 잡을 수 있게 되었다.
