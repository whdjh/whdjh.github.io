프론트엔드 개발자라면 매일 숨 쉬듯이 보는 네트워크(Network) 탭! 하지만 매일 쓰는 기능만 쓰다 보니 막상 다른 버튼들은 낯설게 느껴지는 게 당연합니다.

지금까지 설명해 드린 내용에 현업에서 요긴하게 쓰이는 심화 꿀팁 몇 가지를 더 추가해서, 언제든 꺼내 볼 수 있는 "프론트엔드 개발자를 위한 네트워크 탭 최종 요약본"으로 깔끔하게 정리해 보겠습니다.

---

## 1. API 에러가 났을 때! (디버깅 확인 순서)

API 연동 중 문제가 생기면 당황하지 말고 아래 순서대로 확인해 보세요.

1. Status (상태 코드): 통신 자체가 성공했는지 확인합니다.
   - `200`번대: 성공
   - `400`: 프론트엔드 잘못 (파라미터 누락, 오타 등)
   - `401/403`: 인증/권한 문제 (토큰 만료, 쿠키 없음)
   - `500`번대: 백엔드 서버 에러 (백엔드 개발자에게 제보)
2. Payload (요청 데이터): 내가 백엔드에 보낸 데이터(Body, Query String)가 명세서와 일치하는지 확인합니다.
3. Preview / Response (응답 데이터): 백엔드가 나에게 준 데이터를 확인합니다. `Preview` 탭이 JSON을 예쁘게 접고 펼 수 있게 보여주어 가장 자주 씁니다.
4. Headers (헤더): `Authorization` 토큰이나 `Content-Type` 등이 제대로 세팅되어 날아갔는지 점검합니다.
5. Cookies (쿠키): 세션 기반 인증이나 트래킹 툴을 쓸 때, 요청/응답 시 쿠키가 잘 담겨 있는지 확인합니다.

---

## 2. 상단 툴바 버튼 완벽 가이드 (이 버튼은 이럴 때 쓴다!)

- 빨간색 동그라미 (Record network log): 네트워크 기록을 켜고 끕니다. (항상 켜두는 것이 기본)
- 금지 표시 (Clear): 쌓여있는 로그를 싹 지웁니다.  
  [사용처] 특정 버튼을 클릭했을 때 무슨 API가 호출되는지만 깔끔하게 보고 싶을 때, 이 버튼으로 화면을 지운 후 테스트합니다.
- Filter (깔때기 모양): 필터 바를 켭니다.  
  [사용처] `Fetch/XHR`을 선택해 백엔드 통신 API만 골라볼 때 가장 많이 씁니다.
- Preserve log (로그 보존) ⭐[필수 꿀팁]  
  [사용처] 페이지 이동(Redirect)이나 새로고침 시 기존 로그가 날아가는 것을 막아줍니다. 소셜 로그인이나 결제 연동처럼 페이지가 여러 번 휙휙 바뀌는 로직을 디버깅할 때 이거 안 켜두면 에러 로그를 놓치게 됩니다.
- Disable cache (캐시 사용 안 함) ⭐[프론트 필수]  
  [사용처] 켜두면 브라우저 캐시를 무시하고 항상 최신 데이터를 받아옵니다. "어? 코드 바꿨는데 왜 화면/데이터가 안 바뀌지?" 하는 억울한 삽질을 막아줍니다. 개발자 도구를 열어둘 땐 무조건 체크해 두는 것을 추천합니다.
- No throttling (네트워크 속도 제어):  
  [사용처] `Fast 3G`나 `Slow 3G`로 변경하여 인터넷이 느린 환경을 시뮬레이션합니다. 로딩 스피너(스켈레톤 UI 등)가 유저에게 잘 보이는지 테스트할 때 유용합니다.

## 3. 알아두면 퇴근이 빨라지는 '찐' 꿀팁 (Hidden Gems)

1. "이 API 어디서 호출한 거야?" 찾기 (Initiator 탭)  
   내가 짜지 않은 코드나 복잡한 컴포넌트 트리에서 특정 API가 어디서 쏘아진 건지 찾기 힘들 때, 리스트의 `Initiator` 열에 있는 파일명(ex. `api.ts:42`)을 클릭하면 해당 소스코드로 바로 이동합니다.

2. 백엔드 개발자에게 완벽하게 에러 제보하기 (Copy as cURL / fetch)  
   에러 난 리퀘스트 우클릭 → `Copy` → `Copy as cURL (bash)` 클릭.  
   복사된 텍스트를 백엔드 개발자에게 주면, 그분들이 내 로컬 환경과 동일한 조건(헤더, 쿠키, 파라미터 포함)으로 API를 쏴볼 수 있어 원인 파악이 훨씬 빨라집니다.

3. 화면 조작 없이 API만 다시 쏴보기 (Replay XHR)  
   리퀘스트 우클릭 → `Replay XHR` 클릭.  
   폼을 다시 채우고 버튼을 누르는 귀찮은 과정 없이, 방금 쐈던 API를 그대로 한 번 더 호출해 줍니다.

4. 강제로 에러 상황 만들기 (Block request URL)  
   리퀘스트 우클릭 → `Block request URL` 클릭.  
   브라우저가 해당 API 통신을 강제로 막아버립니다. "API 통신 실패 시 에러 팝업이 잘 뜨나?"를 테스트하고 싶을 때 백엔드 서버를 끄지 않고도 테스트할 수 있는 치트키입니다.

5. 수많은 API 응답 중에서 원하는 값 찾기 (Search 기능)  
   네트워크 탭 좌측 상단의 돋보기 아이콘(Search)을 누르거나 `Cmd/Ctrl + F`를 누르세요.  
   특정 에러 메시지나 유저 ID를 검색하면, 어떤 API의 응답(Response)에 그 값이 들어있는지 한 번에 찾아줍니다.

6. 병목 구간 찾기 (Waterfall 열)  
   리스트 우측의 `Waterfall` 막대그래프에 마우스를 올려보면, 해당 API가 서버에 연결하는 데 오래 걸렸는지(TTFB), 데이터를 다운받는 데 오래 걸렸는지(Content Download) 구간별 소요 시간을 보여줍니다.  
   이를 통해 "서버 응답이 느린 건지, 리소스가 너무 큰 건지" 성능 최적화의 단서를 잡을 수 있습니다.
