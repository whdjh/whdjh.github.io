## 왜 적용하게 되었나?

여러 개의 **input**이 들어가는 **폼**에서, input마다 **상태를 따로** 관리하면 코드가 금방 지저분해졌다.  
일관된 방식으로 관리하려고 **react-hook-form(RHF)**의 **FormProvider**와 **useFormContext**를 도입했다.

---

## 공부 내용

### useForm

#### 개념

- **폼 상태**와 **메서드**를 만드는 훅이다.
- **중앙 폼 상태**를 만들고, input 컴포넌트들이 이 상태를 **공유**한다.
- **FormProvider**는 **Context API**로 methods를 내려주어, **props**를 일일이 넘기지 않아도 된다.

#### 옵션

- **defaultValues**: 초기값 설정
- **mode**: 유효성 검증 **트리거** (onChange, onBlur, onSubmit 등)
- **reValidateMode**: 에러 발생 후 **다시 검증**하는 타이밍

#### 반환값

- **register(name, options)**: input을 RHF에 **등록**
- **handleSubmit(onValid, onInvalid?)**: 제출 **이벤트 핸들러** 반환
- **watch(name?)**: 값 **구독**
- **formState**: 에러·폼 상태
  - **errors**: 필드별 에러
  - **isDirty / dirtyFields**: 값 변경 여부
  - **isValid**: 유효성 통과 여부
  - **isSubmitting / isSubmitSuccessful**: 제출 상태

---

### watch — 값 구독

- **watch()**는 **현재 값**을 읽고, 값이 바뀌면 **컴포넌트를 리렌더**한다.
- 예: `const nameValue = watch("name")`

### register — 이벤트 핸들러 묶음

- **onChange**, **onBlur**, **ref**, **name** 같은 **props**를 반환한다.
- 실제 input에 **spread**해서 연결한다.
- 예: `<input {...register("name", { required: true })} />`

---

## 적용 순서

### 1. 최상위에서 useForm으로 methods 생성

```tsx
const methods = useForm<FormValues>();
```

### 2. FormProvider로 감싸기

```tsx
<FormProvider {...methods}>
  <form onSubmit={handleSubmit(onSubmit)}>...</form>
</FormProvider>
```

### 3. 자식에서 useFormContext로 가져오기

```tsx
const { register } = useFormContext();
```

### 4. input에 register 연결

```tsx
<input {...register("name", rules)} />
```

### 5. 에러는 ErrorMessage로 표시

```tsx
<ErrorMessage
  errors={errors}
  name={name}
  render={({ message }) => (
    <p className="mt-1 text-sm text-red-500">{message}</p>
  )}
/>
```

---

## 결과

- **FormProvider**와 **useFormContext**로 폼 상태를 **전역 컨텍스트**처럼 공유하면서 **재사용 가능한 input**을 만들 수 있게 됐다.
  - **register**를 props로 일일이 넘기지 않아도 된다.
  - input 컴포넌트마다 **같은 패턴**으로 작성할 수 있다.
  - **재사용성**과 **가독성**이 모두 좋아졌다.
