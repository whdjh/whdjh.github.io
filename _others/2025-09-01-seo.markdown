## 공부하게 된 이유

검색 노출은 가끔 도구 점수나 CSR vs SSR 논쟁으로 줄어들어 말해진다.  
하지만 실제로 순위를 바꾸는 건 “검색봇이 무엇을 언제 어떻게 이해했는가”와 “그 이해가 신뢰로 쌓이는가”다.

---

## DIRA

검색 최적화를 네 가지 축으로 나누어 보면 다음과 같다.

1. Discoverability (찾을 수 있는가)  
   URL을 찾을 수 있는가. 내부 링크, 사이트맵, 크롤링 허용, 짧은 리다이렉트 체인.

2. Indexability (찾았을 때 읽을 수 있는가)  
   찾았을 때 즉시 읽을 수 있는가. 의미 있는 HTML, JS 실패에 대한 대비, 상태코드의 명확성.

3. Relevance (봇의 이해 가능성)  
   제목·메타·시멘틱 태그·구조화 데이터·정규화.

4. Authority (정보의 신뢰)  
   내부 링크 그래프, 외부 인용/브랜드, 사용자 만족.

- 이 네 축은 엔진(구글/네이버)과 무관하게 공통 분모다.
- Lighthouse 점수는 D, I의 일부를 자동으로 점검해 주는 도구일 뿐이고, 최종 SEO는 R, A가 크게 좌우한다.

## 생각한 것들

### 1. CSR vs SSR 논쟁의 실제 쟁점

- SSR/SSG는 첫 응답에 본문이 실려 있어서, 봇이 찾았을 때 즉시 읽을 수 있다.
- CSR도 “찾았을 때 읽기”가 가능하지만, 핵심 콘텐츠가 JS 렌더 이후에만 있으면 지연·실패·패리티 불일치에 취약하다.

### 2. 뭘 고려하면서 짜면 좋을까?

- HTML 우선: 핵심 텍스트·링크는 반드시 HTML에 존재.
- 링크는 `<a>`: 중요한 네비게이션은 버튼 클릭이 아니라 표준 링크.
- 정규화: `<title>`, meta description, rel=canonical의 일관성.
- 시멘틱 구조: `header` / `main` / `article` / `section` / `h1`~`h6`로 의도를 드러냄.
- 구조화 데이터(JSON-LD).
- 상태코드 준수: 200 / 301 / 404 / 410 / 503을 의미대로 응답.
- 사이트맵·robots: 자동 갱신되는 sitemap.xml, 불필요한 차단 금지.
- 엔진별 모니터링: Google Search Console(GSC)과 네이버 서치어드바이저로 커버리지·오류·쿼리 의도 확인.

### 3. Lighthouse는 바닥선, 평가는 로그

- Lighthouse SEO는 “색인에 필요한 최소 조건”을 자동 점검하는 것일 뿐, 통과해도 SEO 보장은 아니다.
- 평가는 실제 지표로 하고, 점수는 시작점일 뿐 종료 조건이 아니다.

### 4. “전체적으로 좋다”의 기준

- 구글은 구조화 데이터·링크 그래프에 강하고, 네이버는 자체 서비스 편입 영역이 넓다.  
  다만 기본 HTML·정규화·사이트맵·속도는 둘 다 중요하게 본다.
- 따라서 “전체적으로 좋다”의 기준은 DIRA와 각 엔진 콘솔에서의 커버리지·오류 제로화다.

## 결과

- 좋은 SEO는 검색봇이 지금 당장 읽는 HTML을 중심에 두고, 그 위에 의도에 맞는 콘텐츠 구조와 신뢰 신호를 차곡차곡 쌓는 일이다.
