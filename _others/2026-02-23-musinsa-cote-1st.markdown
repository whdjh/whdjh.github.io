## Node.js 입력 처리 (Buffering Strategy)

- 브랜드정보 → 고객 요청 순서로 들어오는데 고객 요청을 처리하려면 브랜드 사이즈 표가 먼저 전부 메모리에 있어야 한다.
- 따라서 데이터 간에 의존 관계가 있기 때문에 전체 입력을 버퍼링 한 뒤 파싱하는 방식이 적합하다고 생각했다.

---

## 1번 문제

### 로직 정리
```json
1. 브랜드 개수와 고객 수를 받는다
2. 각 브랜드의 사이즈 표를 저장한다
3. 고객마다 원하는 브랜드 + 본인 치수를 받아서
   ├─ 브랜드가 없으면 → UNKNOWN
   ├─ 3부위 다 범위 안에 드는 사이즈가 있으면 → 그 중 가장 작은 거
   └─ 맞는 게 없으면:
       ├─ 3부위 다 제일 큰 사이즈보다 크면 → UP
       ├─ 3부위 다 제일 작은 사이즈보다 작으면 → DOWN
       └─ 그 외 → MISMATCH
```

### 사고
- 지금 입력이 쉽표로 이루어진 구조이므로 브랜드명으로 바로 꺼낼 수 있는 구조로 변경하기 위해 HashMap을 사용했다.
1. 만약 배열의 형태로 간다면 배열이 하나씩 순회하면서 찾아하지만 HashMap을 사용한다면 key로 매칭해서 찾으면 되어 O(1)로 작아진다.

- 고객별 판정 방법
1. 고객의 요청이 들어왔지만, 브랜드의 정보가 없다 -> UNKNOWN
2. 사이즈 표를 가장 작은 것부터 확인해서 키 & 가슴 & 허리 순으로 확인해서 맞으면 그 사이즈 출력
3. 사이즈 표를 확인했는데 안맞으면
1) 제일 큰 사이즈의 최대보다 다 초과 -> UP
2) 제일 작은 사이즈 최소보다 다 미만 -> DOWN
3) 나머지는 MISMATCH

### 코드해설
> "각 터미널의 코드 라인 간의 영향을 안준다"

1. B(브랜드 수)와 Q(고객 수)는 solution 함수 호출 전에 inputData[0]에서 파싱되어 파라미터로 전달되고, inputData[0]은 이미 사용했으므로 lineIdx는 1부터 시작한다.
2. 버퍼 형태로 받기 때문에 입력 라인 위치는 lineIdx로 관리한다.
3. 다음 줄로 이동하여 브랜드명과 사이즈 개수를 받고 분리한다.
4. 브랜드명을 brands 해시맵의 key로 저장한다.
5. 다음 줄로 이동하여 첫 번째 요소를 사이즈 라벨, 나머지를 h_min, h_max, c_min, c_max, w_min, w_max로 매핑한 객체를 만들어 sizeList 배열에 push한다.
6. 고객 수만큼 순회하며
   - 브랜드가 해시맵에 없으면 UNKNOWN 출력 후 continue
   - 있으면 해당 sizeChart를 find()로 순회하여 3부위 모두 범위 안에 드는 첫 번째 사이즈를 찾아 출력한다.
7. 못 찾으면 smallest(첫 번째), largest(마지막) 사이즈를 꺼낸다.
8. isUp: 3부위 모두 largest 최대값 초과 → UP, isDown: 3부위 모두 smallest 최소값 미만 → DOWN, 둘 다 아님 → MISMATCH
