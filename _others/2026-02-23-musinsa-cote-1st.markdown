## Node.js 입력 처리 (Buffering Strategy)

브랜드 정보(Context)가 먼저 주어지고 고객 요청(Query)이 뒤따르는 구조에서는 줄 단위의 실시간 처리(Streaming)보다 전체 데이터를 확보한 후 처리하는 버퍼링(Buffering) 방식이 안전하다고 판단했다.

### 흔한 실수: Streaming 처리

```javascript
for await (const line of rl) {
  // 첫 줄만 읽고 바로 실행하면 뒤따라오는 컨텍스트 정보를 놓칠 수 있음
  solution(line[0], line[2]); 
  rl.close(); 
}

```

### 올바른 접근: Buffering

프론트엔드에서 `Promise.all`로 모든 API 응답을 기다린 후 렌더링하는 것과 같은 논리

```javascript
const readline = require('readline');

(async () => {
  let rl = readline.createInterface({ input: process.stdin });
  let inputData = [];

  // 모든 입력을 배열에 저장 (Buffering)
  for await (const line of rl) {
    if (line.trim() !== '') inputData.push(line.trim());
  }

  // 입력 완료 후 데이터 파싱
  const [B, Q] = inputData[0].split(',').map(Number);
  
  // 전체 데이터를 기반으로 솔루션 호출
  solution(B, Q, inputData);
  
  process.exit();
})();

```

# 사이즈 추천

## 배경

무신사에서는 브랜드마다 사이즈 체계가 다릅니다. 구체적으로, `B`개의 브랜드가 있으며, 각 브랜드에는 여러 사이즈가 있습니다. 각 사이즈는 **키**, **가슴**, **허리**로 총 세 부위의 추천 치수의 **최솟값**, **최댓값**으로 이루어져 있습니다.

아래 규칙에 따라 `Q`명의 고객의 원하는 브랜드와 신체 치수를 기반으로 **브랜드별 추천 사이즈**를 안내하세요.

## 규칙

1. 고객이 원하는 브랜드가 존재하지 않는 브랜드이면 `UNKNOWN`을 안내해야 합니다.
2. 고객이 원하는 브랜드에 대해, 고객의 키, 가슴, 허리 치수 모두 다음과 같은 조건을 만족하는 사이즈를 안내해야 합니다.
   - 해당 부위의 추천 치수의 최솟값 이상 최댓값 이하여야 합니다.
3. 추천 가능한 사이즈가 여럿이면, 가장 작은 사이즈를 안내해야 합니다.
   - 사이즈 순서는 입력 순서입니다.
     - 첫 번째로 주어지는 사이즈가 가장 작습니다.
4. 만족하는 사이즈가 없는 경우 다음과 같이 처리해야 합니다.
   - 고객의 키, 가슴, 허리 치수 모두, 가장 큰 사이즈의 부위별 추천 치수의 최댓값보다 크다면 `UP`을 안내해야 합니다.
   - 고객의 키, 가슴, 허리 치수 모두, 가장 작은 사이즈의 부위별 추천 치수의 최솟값보다 작다면 `DOWN`을 안내해야 합니다.
   - 위 두 경우에 해당하지 않으면 `MISMATCH`를 안내해야 합니다.

## 입력

첫째 줄에 브랜드의 개수 `B`, 고객의 수 `Q`가 쉼표를 두고 주어집니다.

다음 줄부터 `B`개의 브랜드의 정보가 다음과 같이 주어집니다.

- 각 브랜드의 정보의 첫째 줄에는 브랜드명 `S`, 사이즈 개수 `N`이 쉼표를 두고 주어집니다.
- 각 브랜드의 정보의 둘째 줄부터 `N`개의 줄에 걸쳐 사이즈명 `T`, 최소 키 `H_min`, 최대 키 `H_max`, 최소 가슴 `C_min`, 최대 가슴 `C_max`, 최소 허리 `W_min`, 최대 허리 `W_max`가 쉼표를 두고 주어집니다.

다음 줄부터 `Q`개의 줄에 걸쳐 고객이 원하는 브랜드명 `S_want`, 고객의 키, 가슴, 허리 치수 `H, C, W`가 쉼표를 두고 주어집니다.

### 제약 조건

- `1 <= B <= 10`
- `1 <= Q <= 100`
- `S`는 알파벳 대소문자로 이루어진 길이 1 이상 10 이하의 문자열입니다.
- `B`개의 브랜드명은 서로 다릅니다.
- `1 <= N <= 5`
- `T`는 알파벳 대소문자로 이루어진 길이 1 이상 10 이하의 문자열입니다.
- 브랜드별 `N`개의 사이즈명은 서로 다릅니다.
- `100 <= H_min < H_max <= 200`
- `50 <= C_min < C_max <= 150`
- `50 <= W_min < W_max <= 150`
- 브랜드별 `N`개의 사이즈의 각 치수는 주어지는 순서대로 반드시 증가함이 보장됩니다.
  - 각 브랜드에서 첫 번째로 주어지는 사이즈가 해당 브랜드에서 가장 작은 사이즈입니다.
- `S_want`는 알파벳 대소문자로 이루어진 길이 1 이상 10 이하의 문자열입니다.
- `100 <= H <= 200`
- `50 <= C <= 150`
- `50 <= W <= 150`
- 입력으로 주어지는 모든 수는 정수입니다.

## 출력

`Q`개의 줄에 걸쳐 `i`번째 줄에 `i`번째 고객이 **원하는 브랜드명**과 해당 고객한테 **안내해야 하는 결과**를 쉼표를 두고 출력합니다.

## 문제 1. 브랜드별 사이즈 추천 시스템 

이 문제는 무신사의 핵심 기능인 **'실시간 행동 데이터 기반 초개인화 추천'**과 맞닿아 있다. 고객의 신체 치수와 브랜드마다 제각각인 사이즈 표를 매칭하는 프론트엔드 비즈니스 로직 문제이다.

### 목표
- 고객의 신체 정보(키, 가슴, 허리)를 입력받아, 특정 브랜드의 사이즈 표와 대조하여 최적의 사이즈를 추천
- 핵심 조건:
1. 모든 부위가 범위 내에 들어야 함 (AND 조건).
2. 여러 사이즈가 맞으면 가장 작은 사이즈 추천.
3. 맞는 게 없으면 UP(전체 큼), DOWN(전체 작음), MISMATCH(일부 안 맞음)로 예외 처리.

### 접근 방법
- 데이터 전처리 (Parsing): 입력이 쉼표(,)로 구분된 문자열(CSV 형태)이므로, 이를 다루기 쉬운 Object 배열 형태로 변환하는 것이 최우선
- 완전 탐색 (Linear Search): 사이즈 표는 보통 S, M, L 순서로 정렬되어 들어온다. 따라서 앞에서부터 순차적으로 검사해서 첫 번째로 맞는 사이즈를 찾으면 그게 곧 '가장 작은 최적 사이즈'가 된다.
- 예외 처리 (Fallback): 매칭 실패 시, 단순 실패가 아니라 '왜' 실패했는지(너무 커서? 너무 작아서?)를 분석하는 로직이 필요하다.

### 코드 로직

* **Parsing:** CSV 형태의 데이터를 `split(',')`을 통해 브랜드 정보와 고객 요청 분리
* **Lookup Performance:** 브랜드명을 Key, 사이즈 배열을 Value로 하는 **Hash Map**을 생성하여 탐색 시간을 $O(1)$로 최적화.
* **필터링 로직:** find() 메서드를 사용해 키/가슴/허리가 모두 min ~ max 사이인 첫 번째 요소를 찾고, 찾으면 즉시 반환
* **엣지 케이스 로직:** 못 찾았다면, 사이즈표의 제일 작은 값(size[0])과 제일 큰 값(size[last])을 기준으로 고객의 치수와 비교하여 UP/DOWN/MISMATCH를 결정합니다.
* **UX 설계:** 단순 실패(`FAIL`) 처리가 아닌, `UP`/`DOWN` 등의 대안을 제시하여 사용자 경험을 고려.

### Code Review

```javascript
function solution(B, Q, data) {
  // 배열로 버퍼링된 전체 데이터(data)를 순차적으로 읽기 위한 인덱스 포인터
  let lineIdx = 1;
  
  // 브랜드별 사이즈 정보를 O(1) 시간에 탐색하기 위한 Hash Map 객체 초기화
  const brands = {};
  
  // 브랜드 데이터 구조화하여 총 B개의 브랜드 정보를 순회하며 객체에 매핑
  for (let i = 0; i < B; i++) {
    // 첫 줄에서 브랜드명과 해당 브랜드의 사이즈 개수를 분리
    const [brandName, sizeCount] = data[lineIdx++].split(',');
    
    // 해당 브랜드의 사이즈 표를 담을 빈 배열 생성
    const sizeList = [];
    
    // 사이즈 개수만큼 반복하며 사이즈별 상세 범위(min, max) 추출
    for (let j = 0; j < Number(sizeCount); j++) {
      // 사이즈명, 키(h), 가슴(c), 허리(w)의 최소/최대값 데이터를 콤마 기준으로 분리
      const info = data[lineIdx++].split(',');
      
      // 파싱된 문자열 데이터를 Number 타입으로 변환하여 객체 형태로 배열에 추가
      sizeList.push({
        // 사이즈명 (예: S, M, L)
        label: info[0],
        // 키 범위 (Height)
        h_min: Number(info[1]), h_max: Number(info[2]),
        // 가슴둘레 범위 (Chest)
        c_min: Number(info[3]), c_max: Number(info[4]),
        // 허리둘레 범위 (Waist)
        w_min: Number(info[5]), w_max: Number(info[6])
      });
    }
    
    // 완성된 사이즈 배열을 Hash Map의 Value로 할당 (Key: 브랜드명)
    brands[brandName] = sizeList;
  }

  // 고객 매칭 로직: 총 Q개의 고객 요청(Query)을 순회하며 최적의 사이즈를 탐색
  for (let i = 0; i < Q; i++) {
    // 고객 요청 데이터를 콤마 기준으로 분리
    const query = data[lineIdx++].split(',');
    
    // 첫 번째 요소는 고객이 요청한 타겟 브랜드명
    const targetBrand = query[0];
    
    // 나머지 요소(키, 가슴, 허리)는 배열의 slice와 map을 통해 숫자 배열로 변환
    const [userH, userC, userW] = query.slice(1).map(Number);

    // [Validation] 요청한 브랜드가 데이터에 존재하지 않는 경우
    if (!brands[targetBrand]) {
      console.log(`${targetBrand},UNKNOWN`);
      continue; // 즉시 다음 쿼리로 넘어감
    }

    // 타겟 브랜드의 사이즈 표 배열을 가져옴
    const sizeChart = brands[targetBrand];
    
    // Array.find()를 통해 모든 조건(키, 가슴, 허리)을 만족하는 '첫 번째' 사이즈 탐색
    // 사이즈 표가 작은 순서대로 주어졌다고 가정할 때, 가장 작은 최적의 사이즈가 반환
    const matched = sizeChart.find(s => 
      userH >= s.h_min && userH <= s.h_max &&
      userC >= s.c_min && userC <= s.c_max &&
      userW >= s.w_min && userW <= s.w_max
    );

    // 매칭되는 사이즈를 찾았다면 해당 사이즈명(label) 출력 후 다음 요청으로
    if (matched) {
      console.log(`${targetBrand},${matched.label}`);
    } 
    // [Fallback] 모든 조건에 맞는 사이즈가 없을 경우, UX를 고려한 실패 사유 분석 로직
    else {
      // 배열의 첫 번째 요소(가장 작은 사이즈)와 마지막 요소(가장 큰 사이즈) 추출
      const smallest = sizeChart[0];
      const largest = sizeChart[sizeChart.length - 1];

      // 3가지 신체 치수가 모두 '가장 큰 사이즈의 최대값'보다 큰지 확인 (전부 큼)
      const isUp = userH > largest.h_max && userC > largest.c_max && userW > largest.w_max;
      
      // 3가지 신체 치수가 모두 '가장 작은 사이즈의 최소값'보다 작은지 확인 (전부 작음)
      const isDown = userH < smallest.h_min && userC < smallest.c_min && userW < smallest.w_min;

      // 분석 결과에 따라 맞춤형 예외 메시지 출력
      if (isUp) 
        console.log(`${targetBrand},UP`); // 옷이 전체적으로 작으므로 한 치수 큰 브랜드 권장
      else if (isDown) 
        console.log(`${targetBrand},DOWN`); // 옷이 전체적으로 크므로 한 치수 작은 브랜드 권장
      else 
        console.log(`${targetBrand},MISMATCH`); // 일부 치수만 맞지 않아 해당 체형에 맞지 않음을 안내
    }
  }
}
```

# 스토어 픽업 예약

## 배경

무신사 오프라인 스토어에서 온라인 주문 픽업 서비스를 운영합니다. 구체적으로, `S`개의 스토어가 있으며, 각 스토어는 **스토어 ID**, **오픈 시간**, **마감 시간**, **시간당 픽업 한도**, **상품별 재고 정보**가 있습니다.

아래 규칙에 따라 `Q`개의 픽업 예약 요청을 순서대로 처리하세요.

## 규칙

1. 픽업 예약의 스토어 ID가 **존재하는 스토어**여야 합니다.
2. 픽업 예약의 희망 시간은 스토어의 **오픈 시간 이상 마감 시간 미만**이어야 합니다.
   - 예를 들어, 오픈 시간이 10시이고, 마감 시간이 20시라면, 희망 시간은 `10:00` **이상** `20:00` **미만**이어야 합니다.
3. 픽업 예약의 희망 시간이 속한 시간대의 **픽업 예약 수**가 스토어의 **시간당 픽업 한도 미만**이어야 합니다.
   - 여기서 희망 시간이 속한 시간대란, 희망 시간의 분을 제외한 **시간만 의미**합니다.
     - 예를 들어, 희망 시간이 `14:30`이라면, 이는 14**시대**의 예약입니다.
4. 픽업 예약의 요청 수량은 **스토어의 재고 이하**여야 합니다.
5. 픽업 예약에 성공하면, 해당 스토어의 재고가 요청 수량만큼 **차감**되며, 해당 시간대의 **픽업 예약 수**가 1만큼 증가합니다.
6. 요청은 **입력 순서**대로 처리해야 합니다.

## 입력

첫째 줄에 스토어의 수 `S`와 픽업 예약 요청 수 `R`이 쉼표를 두고 주어집니다.

다음 `S`개의 줄에 걸쳐, `i`번째 줄에 스토어 ID `N_i`, 오픈 시간 `L_i`, 마감 시간 `R_i`, 시간당 픽업 한도 `M_i`가 쉼표를 두고 주어집니다. 이는 `N_i`번 스토어에 대한 정보들을 나타냅니다.

다음 `S`개의 줄에 걸쳐, `j`번째 줄에 스토어 ID `N_j`와 **상품별 재고 정보**가 쉼표를 두고 주어집니다. 상품별 재고 정보의 경우, 상품 ID와 수량이 콜론(`:`)을 두고 주어집니다. 이때, `N_j`번 스토어에 재고가 존재하지 않으면, 상품 ID와 콜론, 수량 대신 하이픈(`-`)기호 하나만 주어집니다.

다음 `R`개의 줄에 걸쳐, `k`번째 줄에 요청 ID `P_k`, 스토어 ID `N_k`, 상품 ID `X_k`, 수량 `A_k`, 희망 시간 `T_k`가 쉼표를 두고 주어집니다.

### 제약 조건

- `1 <= S <= 5`
- `1 <= R <= 200`
- `1 <= N_i <= S`
- 주어지는 `N_i`의 값은 모두 다릅니다.
- `0 <= L_i < R_i <= 24`
- `1 <= M_i <= 10`
- `1 <= N_j <= S`
- 주어지는 `N_j`의 값은 모두 다릅니다.
- 하나의 스토어에 존재하는 재고 정보는 5개 이하입니다.
- 상품별 재고 정보가 주어질 때, 상품 ID는 `A001`, `A002`, `A003`, `A004`, `A005` 중 하나이며, 수량은 1 이상 100 이하의 정수입니다.
- `1 <= P_k <= R`
- `1 <= N_k <= 100`
- `X_k`는 `A001`, `A002`, `A003`, `A004`, `A005` 중 하나입니다.
- `1 <= A_k <= 10`
- `T_k`는 `HH:MM`의 형식이며, `00:00`부터 `23:59` 사이의 올바른 시간 형식으로 주어집니다.
- 입력으로 주어지는 모든 수는 정수입니다.

## 출력

주어진 `Q`개의 픽업 예약 요청에 대한 결과를 한 줄에 하나씩 입력 순서대로 출력해야 합니다. 만약 픽업 예약 요청이 성공한 경우, **요청 ID**와 `OK`를 쉼표를 두고 출력하며, 실패한 경우 **요청 ID**와 `FAIL`, **실패 사유**를 쉼표를 두고 출력합니다.

이때 각각의 실패 사유에 따라 출력해야 하는 문자열은 다음과 같으며, 실패 사유가 여러가지인 경우 **우선순위가 가장 높은** 실패 사유만 출력합니다.

| 우선순위 | 사유 | 설명 |
|---------|------|------|
| 1 | STORE | 존재하지 않는 스토어 |
| 2 | TIME | 운영 시간 외 |
| 3 | FULL | 해당 시간대 픽업 한도 초과 |
| 4 | STOCK | 재고 부족 |

이후, `Q+1`번째 줄에 **총 예약 성공 건수**를 출력합니다.

## 문제 2. 스토어 픽업 예약 시스템
이 문제는 무신사의 **'한정판 래플(Raffle)'**이나 **'오프라인 픽업 서비스'**를 시뮬레이션하는 문제이다. 동시성 제어보다는 정해진 규칙에 따른 상태 관리(State Management) 역량을 본다.
오프라인 픽업 서비스를 시뮬레이션하며, **재고(Stock)**와 **시간(Time)**이라는 유한한 자원을 선착순으로 배분하는 문제이다.

### 목표
- 들어온 예약 요청을 순서대로 처리하며 성공/실패 여부를 판별하고, 재고와 예약 수를 갱신.
- 핵심 조건:
1. 가게 존재 여부 확인 (FAIL,STORE).
2. 운영 시간 및 시간당 인원 제한 확인 (FAIL,TIME).
3. 상품 재고 확인 (FAIL,STOCK).
4. 성공 시 재고 차감 및 예약 카운트 증가 (Transaction Commit).

### 접근 방법
- 자료구조 선택 (HashMap): 스토어 ID로 정보를 즉시 찾아야 하므로 Object를 사용한다.
- Fail-Fast 전략: 가장 검사가 빠르고 치명적인 오류부터 먼저 체크합니다. (가게 없음 -> 시간 안 맞음 -> 재고 없음 순서). 이렇게 해야 불필요한 연산을 줄일 수 있다.
- 데이터 정제: 시간 데이터(10:30)에서 분을 버리고 10만 추출하여 정수 비교를 한다.

### 코드 로직
- 데이터 구조화: stores 객체 안에 open, close, limit 뿐만 아니라 stock(재고 객체)과 reservations(시간대별 예약 수 객체)를 함께 묶어서 관리한다. -> 캡슐화
- 유효성 검사 (Validation Pipeline):
```javascript
if (!store) → FAIL,STORE

if (time < open || time >= close || currentRes >= limit) → FAIL,TIME

if (stock < qty) → FAIL,STOCK
```
- 상태 업데이트 (Mutation): 위의 모든 if문을 통과했을 때만 재고를 깎고(-= qty), 예약 수를 늘린다(+= 1).


### Code Review

```javascript
function solution(data) {
    // 배열로 버퍼링된 전체 데이터(data)를 순차적으로 읽기 위한 인덱스 포인터
    let lineIdx = 0;
    
    // 첫 줄에서 스토어 개수(S)와 예약 요청 개수(R)를 파싱하여 숫자로 변환
    const [S, R] = data[lineIdx++].split(',').map(Number);
    
    // 스토어별 운영 시간, 한도, 재고, 예약 상태를 O(1)로 찾기 위한 Hash Map
    const stores = {};

    // 스토어 초기화 (시간, 한도)
    for (let i = 0; i < S; i++) {
        // 스토어 ID, 오픈 시간, 마감 시간, 시간당 예약 한도를 콤마 기준으로 분리
        const info = data[lineIdx++].split(',');
        
        // 스토어 상태(State) 객체 설계: 
        // 하위에 stock(재고)과 reservations(예약 수) 객체를 두어 응집도를 높임
        stores[info[0]] = {
            open: Number(info[1]), 
            close: Number(info[2]), 
            limit: Number(info[3]),
            // 아이템별 재고 상태를 관리할 내부 객체
            stock: {}, 
            // 시간대별 예약 인원을 관리할 내부 객체
            reservations: {} 
        };
    }

    // 재고 정보 매핑
    for (let i = 0; i < S; i++) {
        const info = data[lineIdx++].split(',');
        const id = info[0]; // 스토어 ID
        
        // 아이템 목록 파싱 (예: "itemA:10,itemB:5")
        for (let j = 1; j < info.length; j++) {
            const [itemId, qty] = info[j].split(':');
            // 스토어가 존재하면 해당 스토어의 stock 상태 객체에 아이템 재고량 할당
            if (stores[id]) stores[id].stock[itemId] = Number(qty);
        }
    }

    // 성공한 예약 건수를 추적하기 위한 변수
    let successCount = 0;

    // 예약 요청 처리 (Transaction & Fail-Fast)
    for (let i = 0; i < R; i++) {
        // 예약 요청 데이터 파싱
        const [reqId, storeId, itemId, qtyStr, timeStr] = data[lineIdx++].split(',');
        const reqQty = Number(qtyStr); // 요청한 수량
        
        // '10:30' 같은 문자열에서 ':'를 기준으로 자른 뒤, 분을 버리고 '10'만 추출하여 정수로 변환
        const reqHour = Number(timeStr.split(':')[0]);

        const store = stores[storeId];
        
        // 스토어 검증: 해당 스토어가 존재하지 않으면 가장 먼저 에러 처리 (연산 최소화)
        if (!store) { 
            console.log(`${reqId},FAIL,STORE`); 
            continue; 
        }

        // 해당 시간대의 현재 예약 인원 조회 (없으면 0으로 초기화)
        const currentRes = store.reservations[reqHour] || 0;

        // 시간 및 예약 한도 검증: 요청 시간이 운영 시간 밖이거나, 이미 해당 시간대의 예약 한도가 꽉 찼다면 에러 처리
        if (reqHour < store.open || reqHour >= store.close || currentRes >= store.limit) {
            console.log(`${reqId},FAIL,TIME`);
            continue;
        }

        // 재고 검증: 해당 아이템의 현재 재고 조회 (없으면 0으로 초기화)
        const currentStock = store.stock[itemId] || 0;
        
        // 요청 수량보다 남은 재고가 적다면 에러 처리
        if (currentStock < reqQty) {
            console.log(`${reqId},FAIL,STOCK`);
        } 
        // 모든 검증을 통과한 경우에만 상태(State) 업데이트
      	else {
            // 재고 차감 (안전하게 동기적으로 처리됨)
            store.stock[itemId] -= reqQty;
            
            // 해당 시간대의 예약 인원 증가
            store.reservations[reqHour] = currentRes + 1;
            
            // 전체 성공 카운트 증가
            successCount++;
            
            console.log(`${reqId},OK`);
        }
    }
    
    // 최종적으로 성공한 모든 예약 건수 출력
    console.log(successCount);
}
```
