과거에는 라이브러리를 직접 다운로드해 관리했지만, 프로젝트 규모가 커지며 발생한 **'의존성 지옥'**을 해결하기 위해 패키지 매니저가 탄생했습니다.

---

## 왜 패키지 매니저를 쓰나요?

- **의존성 지옥 (Dependency Hell) 방지:** 라이브러리 간의 복잡한 얽힘을 자동 관리합니다.
- **버전 일관성 유지:** 팀원 모두가 동일한 라이브러리 버전을 사용하여 "내 컴퓨터에선 되는데?" 문제를 방지합니다.
- **관리 효율화:** 수동 관리의 번거로움을 없애고 명령어 한 줄로 설치/업데이트를 완료합니다.

---

## 핵심 개념 용어 사전

| 용어 | 설명 | 비유 |
| --- | --- | --- |
| **node_modules** | 외부 라이브러리 파일이 저장되는 실제 폴더 | **도서관 서고** (책이 꽂혀 있는 곳) |
| **평탄화 (Hoisting)** | 중복 설치 방지를 위해 의존성을 최상위로 끌어올리는 방식 | 서고 정리가 귀찮아 **모든 책을 1층 로비**에 쌓아두는 것 |
| **유령 의존성 (Phantom Dep)** | `package.json`에 없는데 호이스팅 덕분에 코드가 동작하는 현상 | **유령 책**: 대출 목록엔 없는데 로비에 있어서 읽을 수 있는 책 |
| **Lock 파일** | 설치된 패키지의 **정확한 버전**을 기록한 명세서 | **상세 영수증**: "소고기"가 아니라 "A브랜드 1등급 등심"으로 박제 |

## 도구별 상세 분석

### npm (Node Package Manager) - "표준이자 기본"

- **포지션:** Node.js 설치 시 기본 제공되는 표준 도구.
- **구조:** 평탄화(Hoisting) 된 `node_modules`.
- **유령 의존성:** 호이스팅 부작용으로 인한 잠재적 버그 발생 가능.
- **디스크 낭비:** 여러 프로젝트에 같은 라이브러리가 있어도 중복 저장.

### Yarn Classic (v1) - "과거의 영광"

- **포지션:** 과거 npm의 속도 문제를 해결하며 등장했으나 현재는 유지보수 모드.
- **구조:** npm과 거의 동일(평탄화 방식).
- **주의:** 실무에서 "Yarn 쓴다"고 하면 90%는 이 버전을 의미합니다. (기술적 이점은 이제 거의 없음)

### pnpm (Performant npm) - "효율과 안정성"

- **철학:** "중복 저장은 금지, 유령은 퇴치!"
- **구조:**
  - **전역 저장소:** PC 내 모든 패키지 원본을 딱 한 곳에만 저장.
  - **하드 링크:** 전역 저장소의 파일을 프로젝트에서 가리키기만 함 (용량 0).
- **장점:** 유령 의존성 완벽 해결, 디스크 공간 극적 절약.

### Yarn Berry (v2+) - "완전한 혁신"

- **철학:** "node_modules 자체가 비효율의 근원이다. 없애버리자!"
- **구조 (PnP):** 폴더 대신 `.pnp.cjs` 지도 파일과 **Zip 압축 파일** 활용.
- **Zero Install:** 의존성 파일을 Git에 포함시켜, `install` 과정 없이 바로 실행 가능.
- **적합성:** 대규모 모노레포, 빠른 CI/CD가 필요한 환경.

## 최종 비교 요약표

| 구분 | npm | Yarn Classic (v1) | pnpm (추천) | Yarn Berry (v2+) |
| --- | --- | --- | --- | --- |
| **상태** | 표준 (활발) | 레거시 (유지) | **성장 중 (대세)** | 혁신 (활발) |
| **저장 방식** | 파일 복사 (무거움) | 파일 복사 (무거움) | **하드 링크 (가벼움)** | Zip 압축 (가벼움) |
| **node_modules** | 있음 (평탄화) | 있음 (평탄화) | 있음 (가상/링크) | **없음 (PnP)** |
| **유령 의존성** | 발생 | 발생 | **없음** | **없음** |
| **설치 속도** | 보통 | 보통 | 빠름 | **매우 빠름** |
| **난이도** | 하 | 하 | 중 | 상 |
