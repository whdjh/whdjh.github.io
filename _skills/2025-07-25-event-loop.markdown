## 왜 공부하게 되었나?

React, Vue 같은 프레임워크를 사용하면서 **비동기 처리**는 당연하게 써왔다.  
`async/await`, `Promise`, `setTimeout` 등을 쓰면서도 **"왜 이렇게 동작하지?"**라는 의문은 항상 뒤로 미뤄뒀다.

하지만 **복잡한 상태 관리와 비동기 로직이 얽힌 프로젝트**를 진행하면서,  
JavaScript의 **동작 원리**를 모르고서는 더 이상 나아갈 수 없다는 걸 깨달았다.  
특히 성능 최적화나 복잡한 비동기 플로우를 설계할 때, **이벤트 루프**를 모르면 예측할 수 없는 버그가 계속 생겼다.

"JavaScript는 싱글 스레드다", "콜백 큐가 있다" 정도의 얕은 지식으로는 한계가 있었다.  
**진짜 프로페셔널한 개발자**가 되려면 언어의 핵심 동작 원리를 정확히 알아야 한다고 생각했다.

---

## 문제 상황

이벤트 루프를 공부하게 된 계기는 **아주 단순한 코드**에서 시작됐다.  
동료와 JavaScript 실행 순서를 이야기하다 나온 예제였는데, 얼핏 보면 너무 쉬워 보이는 코드였다.

```ts
// 원시값으로 넣으면 stack에 저장
const a = new Number(1);
const b = new Number(2);
const c = new Number(3);

console.log(a);
setTimeout(function () {
  console.log(b);
}, 0);
console.log(c);
```

이 코드를 보자마자 자신 있게 답했다.  
**"당연히 1, 2, 3 순서로 출력되겠지!"**  
`setTimeout`의 지연 시간이 0이니까 바로 실행될 거라고 생각했다.  
하지만 실제로 실행해 보니 결과는 **1, 3, 2**였다.

이 간단한 예제가 **이벤트 루프, 콜 스택, 태스크 큐**를 이해하지 못하고 있다는 걸 깨닫게 해줬다.  
그동안 "그냥 그렇게 동작하는구나" 하고 넘어갔던 것들에 대해 **근본적인 의문**을 갖게 된 순간이었다.

## 공부한 내용

### 1. 힙에 참조 타입 저장

객체, 배열, 함수처럼 **참조 타입**은 **힙(Heap)**에 저장된다.

![힙에 참조 타입 저장](/assets/img/14.png)

---

### 2. 스택과 태스크 큐

**스택**에는 원시 타입이 저장되고, **실제 코드가 실행되는 곳**이다.  
`setTimeout`의 콜백은 **Web API**를 거쳐 **태스크 큐**에 들어간다.  
그래서 스택에는 `console.log(a)`, `console.log(c)` 등만 남게 된다.

![스택과 태스크 큐](/assets/img/15.png)

---

### 3. 스택 실행 후 콜백 큐로 이동

스택에 있는 `console.log(a)`, `console.log(c)`가 **차례대로 실행**되면서 1, 3이 출력된다.  
이후 **태스크 큐**의 콜백은 **콜백 큐**로 이동한다.

![콜백 큐로 이동](/assets/img/16.png)

---

### 4. 콜백 큐 → 스택

**콜백 큐**는 **스택이 비어 있을 때만** 스택으로 콜백을 넣어준다.  
지금은 스택이 비어 있으므로 콜백 큐에 있던 함수가 스택으로 올라간다.

![스택이 비면 콜백 큐에서 스택으로](/assets/img/17.png)

---

### 5. 콜백 실행 및 2 출력

이제 스택에 올라온 **콜백 함수**가 실행되면서 `console.log(b)`가 호출되고 **2**가 출력된다.

![콜백 실행, 2 출력](/assets/img/18.png)

## 깨달은 점

이제 **복잡한 비동기 코드**를 봐도 실행 순서를 예측할 수 있게 됐다.  
**마이크로태스크**와 **매크로태스크**의 우선순위를 이해하니, `Promise`와 `setTimeout`의 실행 순서도 헷갈리지 않는다.

- **성능 최적화 관점 변화**  
  렌더링 최적화할 때 `requestAnimationFrame`을 언제 써야 하는지,  
  `setTimeout` 대신 `queueMicrotask`를 써야 하는 상황이 언제인지 판단할 수 있게 됐다.  
  React의 배치 업데이트나 상태 관리 라이브러리의 동작 원리도 더 깊이 이해하게 됐다.

- **디버깅 실력 향상**  
  "왜 이 코드가 예상과 다르게 동작하지?"라는 상황에서 **이벤트 루프 관점**으로 분석할 수 있게 됐다.  
  콜 스택과 태스크 큐의 상태를 머릿속으로 시뮬레이션하면서 **버그의 원인**을 찾을 수 있다.

브라우저의 내부 동작을 이해한다는 것은 단순히 지식을 늘리는 것이 아니라,  
**더 나은 개발자가 되기 위한 필수 과정**이라는 걸 깨달았다.
