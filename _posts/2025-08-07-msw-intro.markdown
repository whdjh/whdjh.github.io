## 문제 상황

API 서버가 닫혀 있어서 **네트워크 요청 오류**가 나는 상황이었다.  
개발 중에 백엔드 서버가 불안정하거나 사용할 수 없을 때, 프론트엔드 개발을 이어가려면 **API를 모킹**할 필요가 있어서 MSW를 도입했다.

![API 서버 미동작 시 네트워크 오류](/assets/img/28.png)

## MSW란?

**Mock Service Worker(MSW)**는 **Service Worker API**를 이용해 **네트워크 레벨**에서 HTTP 요청을 가로채고, 모의 응답을 주는 라이브러리다.

### 주요 특징

- **Service Worker 기반**: 브라우저와 네트워크 사이에서 프록시처럼 동작
- **실제 네트워크 요청 가로채기**: 실제 API 호출과 같은 방식으로 동작
- **개발/테스트 환경 지원**: 브라우저와 Node.js 모두 지원
- **타입 안전성**: TypeScript와 잘 맞음

### 사용하는 이유

- 백엔드 API가 아직 없거나, 서버가 불안정·종료 상태일 때
- 에러, 로딩 등 **다양한 시나리오**를 테스트할 때
- 네트워크에 의존하지 않고 프론트엔드만 개발할 때
- 실제 API와 **동일한 인터페이스**로 개발·테스트할 때

## 깨달은 점

### 1. 개발 환경에서의 독립성

- 백엔드 서버 상태와 관계없이 **프론트엔드 개발을 이어갈 수 있게** 됐다.
- 서버 다운이나 네트워크 이슈로 **개발이 멈추는 일**을 줄일 수 있었다.

### 2. Service Worker 이해

- Service Worker가 **브라우저와 네트워크 사이에서 프록시** 역할을 한다는 걸 실제로 경험했다.
- 네트워크 요청을 **가로채고 조작하는 원리**를 구현하면서 이해하게 됐다.

### 3. 개발 워크플로우 개선

- API 의존성 때문에 생기던 **병목**을 줄이는 방법을 익혔다.
- **프론트엔드와 백엔드**를 병렬로 개발할 수 있는 환경을 만들 수 있게 됐다.
