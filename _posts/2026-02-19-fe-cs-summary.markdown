## 중요도 5

### 1. 브라우저의 렌더링 원리

> DOM 트리 생성 → CSSOM 생성 → JS 실행 → 렌더 트리 생성 → 레이아웃 → 페인팅

### 2. Reflow와 Repaint가 실행되는 시점

> Reflow는 레이아웃 재계산 과정이고, Repaint는 스타일 변경 시 다시 그리는 과정

### 3. 주소창에 google.com을 입력하면 일어나는 일

> DNS 조회 → TCP 연결 수립 → HTTP 요청 → 서버 응답 → 브라우저 렌더링 파이프라인 실행으로 웹페이지가 표시

### 4. 호이스팅(Hoisting)이란?

> 코드 실행 전에 해당 스코프의 최상단으로 끌어올려진 것처럼 동작

### 5. 클로저(Closure)란?

> 함수가 선언된 시점의 스코프를 기억하여 선언 이후에도 접근할 수 있는 기능

### 6. 렉시컬 스코프란?

> 함수를 **어디서 호출하는지**가 아니라 **어디에 선언했는지**에 따라 스코프가 결정되는 것

### 7. REST API란?

> 웹의 리소스를 클라이언트와 서버가 일관된 방식으로 처리할 수 있도록 하는 설계 원칙

### 8. 리액트를 사용하는 이유는?

> 가상 DOM과 컴포넌트화

### 9. 컴포넌트화란? (props와 state)

- 리액트는 선언형 UI 라이브러리이기 때문에, **상태가 변하면 UI에 자동으로 바인딩**되어 화면이 갱신됩니다.
- 상태는 컴포넌트의 UI를 결정하는 객체 데이터라고 볼 수 있으며, 일반적으로 `useState`나 `useReducer`로 관리합니다.
- 다만, 렌더링과 무관하게 값을 저장하거나 참조할 필요가 있을 때는 `useRef`로도 상태를 관리할 수 있습니다.

### 10. CSS에서 `position`이란?

> `static`, `relative` // `absolute`, `fixed` // `sticky`

### 11. CSS에서 `display`란?

> Flexbox: 1차원 // Grid: 2차원

### 12. CSS에서 `margin`과 `padding`이란?

> `margin`은 바깥 여백 // `padding`은 안쪽 여백

## 중요도 4

### 1. `this`의 용법

> `this`는 호출 패턴에 따라 다른 객체를 참조하고, 실행 컨텍스트가 생성될 때마다 `this`의 바인딩이 일어남

### 2. 브라우저 저장소의 차이점

> 브라우저 저장소는 클라이언트 방식에는 `localStorage`, `sessionStorage`가 있고, 서버 방식에는 쿠키가 있다.

### 3. JS는 어떤 언어일까?

> 싱글 스레드이면서 논 블로킹 언어

### 4. JavaScript에서 비동기적으로 코딩하기

> 비동기를 적용하는 방법은 콜백 함수, `Promise`, `async/await`가 있다.

### 5. Event Loop

> 이벤트 루프는 힙, 스택, 큐로 이루어져 진행된다.

![JavaScript Event Loop 다이어그램](/assets/img/109.png)

### 6. 마이크로태스크 큐, 태스크 큐

> 큐에는 마이크로태스크 큐와 태스크 큐가 있다.

### 7. 이벤트 전파 (캡처링, 타깃, 버블링)

> 캡처링(상위 → 하위), 타깃, 버블링(하위 → 상위) 단계를 통해 DOM 트리를 따라 이벤트가 전파됨.  
> `event.stopPropagation()`을 사용해 전파를 막을 수 있음.

### 8. 실행 컨텍스트

> 실행할 코드에 제공할 환경 정보들을 모아놓은 객체

### 9. SPA, MPA의 차이

> SPA는 갱신될 부분만 요청, MPA는 변경사항이 있을 때마다 전체 페이지를 요청

### 10. CSR, SSR의 차이

> CSR은 기본 틀만 받고, 브라우저에서 JS가 동작하며 DOM을 그리는 방식이고, SSR은 이미 다 만들어진 DOM을 서버에서 받아오는 방식.

1) **CSR**  
   - 클라이언트 측에서 렌더링을 담당하여 첫 로딩에 빈 HTML 파일에 필요한 번들 파일을 모두 다운로드 받음  
   - **장점:** 화면 깜빡임 없음, 초기 로딩 이후 구동 속도 빠름  
   - **단점:** 초기 구동 속도가 느림

2) **SSR**  
   - 서버 측에서 렌더링 될 페이지를 그려 클라이언트로 내려주는 방식으로, 요청 즉시 HTML 파일을 만듦  
   - **장점:** 초기 로딩 속도 빠름, SEO에 유리  
   - **단점:** 페이지 이동 시 화면 깜빡임이 발생할 수 있음

![CSR vs SSR 다이어그램](/assets/img/110.png)

### 11. `null`, `undefined`, `undeclared`, `NaN`

> `undefined`는 값이 할당되지 않은 상태(자동 할당), `null`은 의도적으로 값이 없음을 표현한 상태(수동 할당), `undeclared`는 선언되지 않음, `NaN`은 표현 불가능한 수치형 결과

## 중요도 3

### 1. HTML 렌더링 중에 JavaScript가 실행되면 렌더링이 멈추는 이유

> 렌더 트리가 불안정해지는 것을 막기 위함

### 2. `require`와 `import`의 차이점

> `require`는 동기적, `import`는 (로드 관점에서) 비동기적

### 3. `var`, `let`, `const`의 차이점

> `var`는 변수 재선언과 재할당 모두 가능한 함수 스코프,  
> `let`은 변수 재선언은 불가능하지만 재할당은 가능한 블록 스코프,  
> `const`는 변수 재선언과 재할당 모두 불가능한 블록 스코프

### 4. CORS (Cross-Origin Resource Sharing)

> CORS는 출처가 다른 서버 간의 리소스 공유를 허용하는 메커니즘

### 5. React의 라이프 사이클

> React의 라이프 사이클은 마운트 → 업데이트 → 언마운트

1) **마운트**: 컴포넌트 인스턴스가 생성되어 DOM에 삽입될 때 순서대로 호출  
2) **업데이트**: `props`나 `state`가 변경되면 렌더(갱신)가 진행되며 순서대로 호출  
3) **언마운트**: 컴포넌트가 DOM에서 제거될 때 호출

![React 라이프사이클 다이어그램](/assets/img/111.png)

### 6. 리액트 리렌더링 과정

> Trigger 단계 → Render 단계 → Commit 단계로 리렌더링 과정이 일어남

1) **Trigger 단계**: `state`나 `props`가 변경될 때 React가 리렌더링을 시작  
2) **Render 단계**: 변경된 상태를 기반으로 Virtual DOM을 만들고, 이전 Virtual DOM과 비교하여 어떤 부분이 바뀌었는지 확인 (아직 실제 DOM에는 반영되지 않음)  
3) **Commit 단계**: 변경된 부분만 실제 DOM에 적용하여 화면에 반영

### 7. `props`와 `state` 차이

> `props`는 부모 → 자식으로 전달되는 읽기 전용 값, `state`는 컴포넌트 내부에서 관리하는 상태

### 8. 리액트에서 `index`를 `key` 값으로 사용하면 안 되는 이유

> 불필요한 리렌더링과 상태 관리 오류를 유발할 수 있음

### 9. TS에서 `type`과 `interface`의 차이

> `type`은 유니온 타입 등 **복잡한 타입** 표현에 유리하고, `interface`는 **객체 타입 설계**와 확장에 유리

### 10. 함수 표현식과 함수 선언식 차이

> 함수 선언식은 호이스팅이 되어 코드의 어디서든 호출이 가능하지만, 함수 표현식은 변수에 할당된 후에만 사용 가능

### 11. HTTP vs HTTPS

> HTTP는 암호화가 없고, HTTPS는 데이터를 암호화하여 중간에서 보더라도 무의미한 암호문으로만 보이게 함

### 12. TLS

> TLS는 공개키 암호화(계산 비용 높음)로 시작하고, 이후 대칭키 암호화로 실제 데이터 전송

### 13. TCP vs UDP

> TCP는 연결 지향 프로토콜, UDP는 비연결형 프로토콜

### 14. Promise

> 비동기 작업을 관리하는 객체로, `pending`, `fulfilled`, `rejected` 세 가지 상태를 가지며 비동기 코드의 가독성을 높임

## 중요도 1

### 브라우저 렌더링 파이프라인

1. **CRP (Critical Rendering Path)**: 브라우저가 HTML·CSS·JS를 DOM과 CSSOM으로 파싱해 렌더 트리를 구성하고 레이아웃, 페인트, 합성을 거쳐 픽셀로 출력하기까지의 경로
2. **DOM (Document Object Model)**: 브라우저가 HTML 문서를 트리 구조의 객체로 표현해 JavaScript가 접근·조작할 수 있게 한 모델
3. **CSSOM (CSS Object Model)**: 파싱된 CSS를 노드 기반 트리로 구조화해 각 노드의 계산된 스타일에 접근할 수 있게 한 모델
4. **렌더 트리 (Render Tree)**: DOM과 CSSOM을 결합해 **화면에 표시될 노드만 포함**하는 트리로, 레이아웃과 페인트의 입력
5. **Layout (Reflow)**: 렌더 트리의 각 노드에 대한 뷰포트 기준 위치와 크기를 계산하는 단계
6. **Paint**: 레이아웃이 확정된 노드들을 실제 픽셀로 그려 래스터화하는 단계
7. **Reflow**: 스타일이나 콘텐츠 변화로 레이아웃 수치가 바뀔 때 영향 받은 노드들의 위치와 크기를 다시 계산해 렌더 트리를 갱신하는 과정
8. **Repaint**: Reflow 결과나 시각적 속성 변화에 따라 변경된 영역을 다시 그리는 과정
9. **Containing Block (컨테이닝 블록)**: 요소의 위치와 크기를 지정하는 데 기준이 되는 블록

### 주소/식별 계층

1. **도메인**: 각 IP에 이름을 부여하는 것
2. **DNS (Domain Name System)**: 사람이 읽는 도메인 이름을 기계가 통신에 사용하는 IP 주소로 변환하는 분산형 이름 해석 시스템
3. **URL (Uniform Resource Locator)**: 인터넷 자원의 위치와 접근 방법을 나타내어 해당 자원에 접근하도록 지시하는 식별자
4. **URI (Uniform Resource Identifier)**: 리소스를 식별하기 위한 문자열의 총칭으로 URL과 URN을 포함하는 상위 개념
5. **자원 (Resource)**: 웹에서 사용되는 모든 자료를 의미

### 통신 계층

1. **프로토콜**: 네트워크에서 상호 운용을 위해 통신의 규칙·형식·절차를 표준화해 정의한 규약
2. **IP**: 목적지 IP 주소를 기반으로 패킷을 전달하는 비연결형·비신뢰성의 네트워크 계층 데이터그램 프로토콜
3. **HTTP**: 주로 TCP를 통해 클라이언트와 서버가 요청·응답 메시지로 통신하는 애플리케이션 계층 프로토콜
4. **프록시**: 클라이언트와 서버 사이에서 요청과 응답을 대신 전달·필터링·캐싱해 보안·성능·접근 제어를 제공하는 중계 서버

### 네트워크 보안/터널링

1. **전송 모드**: IPSec에서 IP 패킷의 내용(payload)만을 보호하는 모드
2. **터널 모드**: IPSec에서 IP 헤더까지 포함한 전체 패킷을 캡슐화해 보호하는 모드
3. **루프백**: 운영체제가 제공하는 가상 네트워크 인터페이스로, 외부 네트워크를 거치지 않고 호스트 자신으로 패킷을 되돌려 사용하는 메커니즘

### 언어/런타임

1. **파싱**: 텍스트나 소스 코드를 토큰화하고 문법 규칙에 따라 내부 표현으로 변환해 실행·분석이 가능하게 만드는 과정
2. **인터프리팅**: 소스 코드를 실행 시점에 순차적으로 분석·변환하여 즉시 실행하는 방식

### JavaScript

1. **인스턴스**: 클래스 정의를 바탕으로 생성된 개별 객체
2. **바인딩**: 프로그램의 어떤 기본 단위가 가질 수 있는 구성요소의 구체적인 값을 확정하는 것
3. **`new`**: 생성자 함수를 호출해 새 객체를 만들고 해당 객체의 `this`와 `prototype`을 설정하는 연산자
4. **`call`**: 함수를 즉시 호출하면서, 첫 번째 인자로 전달한 값에 `this`를 바인딩하는 메서드
5. **`apply`**: 함수를 즉시 호출하되 `this`를 첫 번째 인수로 지정하고, 인수들을 배열의 요소 목록으로 전달하는 메서드
6. **`bind`**: `this`와 일부 인수를 고정한 새 함수를 반환하는 메서드

### 웹 인증·세션/상태 관리

1. **쿠키**: 웹 사이트가 사용자의 브라우저에 저장하는 작은 기록 정보 파일
2. **세션**: 서버에 저장되는 사용자 상태 정보로, 세션 ID를 통해 클라이언트를 식별하며 보통 쿠키로 ID를 교환하는 인증·상태 유지 방식
3. **JWT**: JSON 클레임을 서명해 서버 상태 없이 인증·권한 정보를 전달하는 자체 포함 토큰

### 실행/동시성

1. **스레드**: 어떠한 프로그램 내에서, 특히 프로세스 내에서 실행되는 흐름의 단위
2. **비동기 처리**: 특정 로직의 실행이 끝날 때까지 기다려주지 않고 나머지 코드를 먼저 실행하는 방식
3. **콜백**: 특정 시점에 호출되는 함수
4. **Garbage Collector**: 루트에서 도달 불가능한 객체를 식별해 메모리를 자동으로 회수하는 런타임 메모리 관리 시스템
