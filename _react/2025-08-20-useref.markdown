리액트 훅 시리즈 다섯 번째 — `useRef`로 리렌더 없이 값을 유지하는 방법을 정리한 글이다.

원본링크: https://velog.io/@wngns9807/useRef

---

## 왜 공부하게 되었나?

프로젝트를 하다 보니 useState만으로는 해결이 안 되는 상황이 자주 있었다.  
그때 "그냥 useRef 쓰면 돼"라는 말만 듣고 쓰니까 해결은 됐는데, "이게 뭔데?"라고 물었을 때 머리가 하얘지는 경험을 했다.  
그래서 정리해보기로 했다.

useRef는 UI에 보여줄 필요는 없지만, 내부적으로 꼭 기억해야 하는 값을 다룰 때 주로 쓴다.[^1]

---

## 문제 상황

운동 템포 앱을 만들 때 겪었던 상황이다.

```tsx
function Timer() {
  const [intervalId, setIntervalId] = useState<number | null>(null);

  useEffect(() => {
    const id = window.setInterval(() => {
      console.log("tick");
    }, 1000);

    setIntervalId(id); // 불필요한 리렌더링 발생
    return () => clearInterval(id);
  }, []);

  return <div>타이머 실행 중...</div>;
}
```

여기서 setIntervalId(id)가 실행되면서 컴포넌트가 한 번 더 리렌더됐다.  
화면에는 달라진 게 없는데 성능만 낭비되는 상황이었다.

---

## 공부 내용

- useRef(initialValue)는 `{ current: initialValue }` 형태의 객체를 반환한다.
- current에 값을 넣어도 리렌더링이 일어나지 않는다.
- 렌더링이 반복돼도 같은 ref 객체가 유지되므로, 타이머 ID, DOM 노드, 외부 라이브러리 인스턴스 등을 보관하기 좋다.[^2]

즉, UI에 필요 없는 값은 state 대신 ref에 두는 게 맞다는 걸 배웠다.

---

## 결과

```tsx
function Timer() {
  const intervalId = useRef<number | null>(null);

  useEffect(() => {
    intervalId.current = window.setInterval(() => {
      console.log("tick");
    }, 1000);

    return () => clearInterval(intervalId.current!);
  }, []);

  return <div>타이머 실행 중...</div>;
}
```

- intervalId.current에만 값을 넣기 때문에 리렌더링이 발생하지 않는다.
- UI에는 영향을 주지 않으면서 내부 로직은 그대로 동작한다.
  - 비슷한 예: input의 focus는 “포커스됐다”만 알면 되고, 굳이 true/false를 state로 두고 리렌더할 필요는 없다. 이런 “기억만 하면 되는 값”에 ref가 맞다.
- ref는 DOM 접근용만이 아니라, “리렌더 없이 값을 들고 있는 저장소”라고 보면 된다.
